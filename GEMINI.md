# Конституция проекта SoundCloud-Ultimate

Данный документ фиксирует нерушимые правила архитектуры, вёрстки, работы с данными и приёмки кода для всех задач и агентов в проекте `SoundCloud-Ultimate`.

---

## 1. Архитектура проекта
* **Гибридная модель**: Разрешено использовать **ТОЛЬКО** связку:
  - `crates/sc-core`: 100% Rust-бэкенд (аудио-пайплайн, работа с сетью, кэширование, декодирование, клиент SoundCloud API).
  - `desktop/`: Богатый визуальный интерфейс приложения.
* **Строго запрещено**:
  - Никаких мобильных/Android платформ и обвязок.
  - Никаких интеграций `antidpi`, `zapret` и сторонних сетевых обходов.
  - Никакого примитивного `iced`-интерфейса или переписывания UI на сырые Rust GUI библиотеки.

---

## 2. Запрещённые вкладки и UI-элементы
Следующие элементы интерфейса были навсегда упразднены и **никогда не должны возвращаться**:
* Вкладка `STUDIO & TOOLS`
* Вкладка `Plugins`
* Вкладка `Downloads`
* Обёртка `Library`
* Кнопка колокольчика уведомлений в шапке
* Переключатель тем `Themes`

---

## 3. Закон вёрстки окна
* **Фиксированный каркас**:
  - Верхний **Titlebar** (с полем поиска и кнопками управления окном) — строго зафиксирован (`flex-shrink: 0`).
  - Левый **Sidebar** (навигация) — строго зафиксирован (`flex-shrink: 0`).
  - Нижний **Player** (панель воспроизведения) — строго зафиксирован (`flex-shrink: 0`).
* **Область прокрутки**:
  - Скроллится **ТОЛЬКО** внутренний контейнер контента (`main-content` / внутренний скролл-вьюпорт). Шапка и навигация никогда не должны уезжать при скролле.
* **Модальные окна**:
  - Все модалки имеют базовые стили: `position: fixed; inset: 0; display: none !important; z-index: 1000;`.
  - Модальное окно становится видимым **исключительно** через добавление CSS-класса `.open`.

---

## 4. Закон данных SoundCloud
* **Никаких демо-заглушек и фейковых моков!** Вся функциональность должна работать с реальным SoundCloud API.
* **Лайки (`Likes`)**: Обязательная поддержка постраничной загрузки (пагинации) по ссылке `next_href` для отображения всех треков (> 49 треков).
* **Плейлисты и альбомы**: Если API возвращает только список ID или урезанные объекты, полные метаданные треков обязаны догружаться батчами через `/tracks?ids=...`.
* **Артисты**: Список отслеживаемых артистов загружается из реального эндпоинта `/users/{id}/followings`.

---

## 5. Обязательный пайплайн проверки перед отчётом
Любое изменение перед сдачей задачи пользователю должно пройти 3 этапа проверки:
1. **Rust / Backend**: `cargo clippy` — проверка качества кода без предупреждений и ошибок.
2. **Frontend**: `biome check` — статический анализ JS/CSS без слома структуры.
3. **E2E / Playwright**: Проверка headless-браузером:
   - 0 ошибок в консоли браузера (`console.error`).
   - `visibleModalsCount === 0` при старте (никаких залипших или самопроизвольно открытых оверлеев).
   - Шапка Titlebar и Sidebar остаются на месте при активном скролле контента.
